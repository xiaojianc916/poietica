# Poietica 架构规范与设计哲学

本 skill 是 `AGENTS.md`（宪法）与 `Project Architecture Design/附录 A、B`（目标态）的**可执行读法**：把"该放哪、该叫什么、该由谁写"变成一步步的判据，而不是感觉。

**不重抄原则**：凡是代码里已有单一产地的事实（分层表、禁用目录名、依赖版本、IPC 清单、帧形状、磁盘布局），本 skill 只给**当前路径指针**，不复制内容。复制即制造第二个事实，第二个事实必然分叉。

## 何时使用

- 要新建一个模块 / 包 / crate / 文件，或犹豫它该放哪
- 要拆文件或合并文件
- 命名拿不准，想用 `utils` / `core` / `v2` / `new` 之类
- 要写或改 `CHARTER.md`
- 加一家 agent、一条 IPC 命令、一种帧、一项持久化、一块 UI
- 评审 / 重构改动，判断它是否让架构偏移

## 七条设计哲学

1. **唯一真相，单一写入路径。** 事件账本是唯一真相；投影可删可重建，所以它不是真相。每一类状态只有一个所有者、一条写入路径。禁影子状态、禁兜底副本、禁同名双导出。
2. **目录名 = 能力，文件名 = 该能力的一个事实。** 禁技术种类名与万能桶名，禁时间性命名。看到名字就知道它干什么，不靠猜。
3. **四问四答。** 每个模块根必须答：我是什么 / 我拥有什么 / 谁可调用我 / 我不许知道什么。答不上来的模块不得建立。
4. **端口与适配，组合根只接线不裁决。** 领域定义 ports，适配层实现，组合根注入。薄的判据：凡不需要 `AppHandle`/`State`/`Emitter` 就能写出的逻辑，必须住进 crate 并自带单测。
5. **生成而非手抄。** 契约、协议模型、IPC 绑定一律生成，生成物禁手改，CI 守漂移。手抄协议类型的那一天，就是它开始落后的那一天。
6. **顺序即不变量。** 写字节先于写账、删账先于删字节；唯一合法中间态必须是"会被自动回收的那一种"。取消是状态迁移，不是错误。
7. **架构由机器执行。** 规则住在 `tools/architecture/`，文档只指向它。人读副本写"为何如此"，不写会腐烂的清单。

## 五层一向

依赖只向下，同层之间不许有边；反向调用一律走 ports（依赖倒置）。

| 层 | 职责 | 不许知道 |
| --- | --- | --- |
| L5 组合根 | 装配与入口 | 业务规则 |
| L4 界面表现 | 像素与交互手感 | 账本、协议、进程 |
| L3 边界适配 | 与外界打交道的唯一居所 | 领域内部结构、界面 |
| L2 领域内核 | 产品的真相与不变量，零 IO | 数据库、协议、窗口、界面 |
| L1 公共词汇 | 错误、时钟、生成契约 | 任何业务 |

详细环表、宿主 API 白名单与现状差异见 `LAYERS.md`。

## 工作流（按顺序，别跳）

1. **定层** —— 它属于哪一层？见 `LAYERS.md`。
2. **定归属** —— 哪一类状态归它？走 `PLACEMENT.md` 的路由程序。
3. **定名** —— 过 `NAMING.md` 的禁用清单。
4. **立宪章** —— 模块根写 `CHARTER.md`，四问四行。
5. **验收** —— `bun run check`；涉 IPC 另跑 `bun run ipc:check`。新增架构规则时，把规则写进 `tools/architecture/` 而不是文档。

评审已有改动时走 `REVIEW.md`。

## 一句自检

数据从**协议适配**进来 → 经**领域内核**裁决 → 写进**事件账本（唯一真相）** → 投影为快照 → 由**界面表现**只读渲染；反向只有三条命令路，且均为"先落账、再执行"。
