# 归属：新东西放哪里

## 第 0 步：四问四答（答不出来就别建模块）

模块根的 `CHARTER.md` 只写四行：我是什么 / 我拥有什么 / 谁可调用我 / 我不许知道什么。

**知识归属决定位置，这是第一判据。** 位置错了，后面全错。

## 第 1 步：走扩展路线，别发明新路

| 要加的东西 | 唯一路径 | 验收 |
| --- | --- | --- |
| 一家 agent | `agent-catalog` 加档案（program / args / homeVar / ownHomeDirectory / installSpec / 方言） | **通用层零改动**；专属行为走档案能力开关或该 agent 专属模块 |
| 一条 IPC 命令 | Rust 定类型 → 挂进 `ipc/mod.rs` 的 `surface()` → `bun run ipc:generate` → TS 端口层适配 | TS 侧先写形状即为缺陷 |
| 一种帧 | `crates/.../frame.rs` 加 variant | 两侧由编译器与生成绑定兜底 |
| 一个包 / crate | 先在 `layering.ts` 定层，再建目录 | 架构检查通过 |
| 一项持久化 | ledger 迁移**只追加** | 一条 shipped 的迁移永不修改 |
| 一块 UI | R3 包；状态来自 R1 的派生视图 | UI 里不出现业务判据 |
| 一份协议 | 契约由 server 自述，快照钉在 `contracts/`，生成模型 | `bun run kap:spec:check` 守漂移 |

## 第 2 步：厂商专属知识只住两处

agent 专属知识只允许住在 **`agent-catalog` 的档案**（数据）或**以该 agent 命名的专属模块**（代码）。通用层出现 `if agent_id == "某家"` 即为缺陷。

## 第 3 步：文件该拆还是该合

**拆分判据（出现任一才拆；行数本身不是理由）：**

1. 同一个 enum/union 在同文件两处 match 分发（第二个判别式主干）；
2. 同居两种寿命的状态（进程级与连接级、会话级与轮次级）；
3. 同时服务两类读者（协议解码 + HTTP 应答 + 校验同居）；
4. 模块头注释无法用一句话说清职责。

超过 800 行且不满足以上任一条 → 不拆，在模块头写明为什么内聚。

**合并判据：** 同一判据的两半必须同文件（例：格式判定表把文件头、Content-Type、扩展名收成一张表）。两处实现同一规则（两份时钟、两份解析）即为缺陷，向单一产地收敛。

## 第 4 步：微型架构（文件内部）

- **单一分发点**：一种帧/一种状态只允许一个 match/switch 主干；协议知识收在一处，别处出现协议判别即为泄漏。
- **成形与投递两段式**：昂贵构造在锁外/号外完成，占号、上锁、发布只做最后一步。
- **store 形制（TS）**：不可变快照 + subscribe + 单一 `#commit` 写点 + 引用不变则不通知；动作是箭头字段（引用终生稳定）；派生视图只在其输入变化时重算。
- **时钟、序号、路径等基础设施单点发放**；同款逻辑第二份出现即为缺陷。

## 第 5 步：一次换干净

替换旧实现必须同一次改动删掉旧路径。禁兼容层、禁开关双活、禁无期限迁移设施。一次性迁移代码必须写明删除条件与预计删除时间，条件满足即删。
