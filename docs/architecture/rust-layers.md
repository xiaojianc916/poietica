# Rust 执行边界

依赖环由 `tools/architecture/layering.ts` 检查，工作区成员由 Cargo 管理。

## 领域与能力

- `crates/conversation`：领域事件、准入、轮次和投递不变量，不认识 Tauri。
- `crates/ledger`：SQLite 事务及有界执行 actor；会话身份由这里条件绑定。
- `crates/kap-client`：agent 协议与连接能力；模型经过仍由官方 transcript 提供。
- `crates/asset`：资产格式、注册表和内容寻址存储；包含文件 IO，归能力环。

## 会话用例

`crates/conversation-runtime` 依赖上述能力，不反向依赖应用。
它拥有同一对话的寻址临界区、准入投递、帧落账和延迟处置执行。
寻址锁只管理活动调用，不缓存会话身份；失败恢复不能覆盖已有绑定。
帧日志接受显式账本及发布出口；提交成功后才发布，持久化失败不能被 flush 清除。
处置只有在远端确认成功后销账，响应丢失保留原意图。

## 宿主

`apps/desktop/src-tauri` 解析平台路径、装配依赖、管理进程边界、映射 IPC 和错误。
最终退出先关闭重新启动/安装连接的入口，再断连并回收帧工人。
普通断连不销毁进程级执行设施，以允许后续正常重新连接。

## 真相与边界

会话绑定、本机准入与引用归 SQLite；模型经过归官方 transcript；字节归资产仓。
生成的 IPC 类型不手改；UI 投影不是另一份可独立写入的领域真相。
这份说明限定已收敛的会话执行边界，不宣称自动化或全部宿主业务已经独立。
