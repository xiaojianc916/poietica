# ADR-013：omp 升级流水线

状态：通过；P7 持续实施。

背景：omp 是唯一引擎，升级要快且不能静默破坏；历史集成落在内部接口上。

决策：

- omp 版本在根 `package.json` 与 overrides 中精确锁定，升级显式提交。
- 只允许从 `@oh-my-pi/pi-coding-agent` 的公开导出与 `omp-types` 门面导入；深层 import 由只减不增闸门看守。
- 录制事件/工具样本作为一致性测试；升级后全部样本必须通过。
- 未识别的事件与工具不丢弃：以 notice 类事件透传并进入升级变更报告。
- SDK 参考文档中的名字与行号由 `check:omp-doc` 对随包 omp 机检。
- 正式适配前，未知能力以通用卡片显示；一个发布周期内补齐正式入口。

后果：

- 升级失败可回退到上一个精确版本与配套 Core。
- 每次 omp 升级必须附变更报告，说明新增/变更/消失的导出、事件与工具。
