# 0037 — omp 18.5.0 的设置走注册表，技能轮按官方判据上屏

## 状态

已接受，已落地。改 `packages/agent-bridge`（settings / settings-labels /
settings-descriptions / catalog / expected-state / bridge）、`packages/conversation`
（omp-tool-view / omp-tool-glyphs）与 `package.json` 的 catalog（omp 18.3.0 → 18.5.0）。
不动 IPC 契约、不动落盘布局、不动传输的线上形状。

## 背景

升级 omp 18.3.0 → 18.5.0 时，上游删掉了两样我们正踩在上面的东西，另有两处技能轮的
屏幕事实一直是坏的 —— 四件事都是**静默**的：编译期或测试红了才知道，而屏幕上看不出少了什么。

### 一、`config/settings-schema.ts` 整支消失

18.3.0 那份是 6390 行的单一 schema 事实源（503 键 / 378 格带 ui 元数据），导出
`SETTINGS_SCHEMA` / `getUi` / `getType` / `getDefault` / `getEnumValues` /
`isCredential` / `hasUi`。18.5.0 改成**注册**模式：各域自己 `register()`（`session/settings.ts`、
`config/model-settings.ts`…），`config/registry.ts` 给类型化句柄 `Setting`，
`config/all-settings.ts` 的 `orderedSettings()` 汇总（529 键 / 397 格带 ui）。
老 API 一个都不剩。

### 二、`Settings.get(path)` / `set(path, value)` 也没了

18.5.0 的读写都走句柄：`setting.get(scope)` 读，`setting.set(scope, v)` 落全局层、
`setting.override(scope, v)` 落运行时层。鸭子类型的假 Settings（测试里那种
`{ get, set, flush }`）会直接在 SDK 内部炸（`scope.valueCache` 取不到）。

### 三、技能轮被当成助手正文铺上屏

技能以 `role: 'custom'` + `customType: 'skill-prompt'` + `attribution: 'user'` 进显示经过，
而桥的开轮判据只认 `role === 'user'`。于是整份 SKILL.md 落进那一轮的第一步，被铺成
**助手正文** —— 屏幕上多出一段用户从没说过的话。

### 四、技能轮的两个读者都读错了地方

- chip 的真产地是 `origin.payload.skillActivations`，而重投影那条路（`turnOp`）写死
  `origin: { kind: 'user' }`。每一轮 `agent_end` 都会重投影，所以 chip 在「已处理 N 秒」
  出现的那一刻被擦掉。
- 投递时只把 chip 上那格 args 交给 `buildSkillPromptMessage`，而调色板插进来的 chip
  是 `DecoratorNode`、`getTextContent()` 交回空串 —— args 永远缺席，官方模板里的
  `{{#if userArgs}}` 整段被省掉，**用户那句话根本没进上下文**。模型回「没收到信息」是实话。

## 决定

**四处都走官方形状，不自造第二套。**

1. **设置**：按 path 寻址收敛到 `config/registry.ts` 的 `lookup`（官方门面），
   `settings.ts` 出 `settingValueOf` / `writeSettingValue` / `settingsReaderOf` 三个薄封装 ——
   目录要逐格走完上游那张表（294 格），不可能为每格绑一个 import。
   `config/all-settings.ts` 是**副作用 import**：不加载它注册表是空的，目录会静默变成 0 格。
   认不出的 path **如实抛**，与老 `Settings.get` 同义。

2. **读写语义照旧**：老 `get` = 各层合并后取值、谁都没配就是默认；老 `set` = 落全局层后台保存。
   `Setting.get` / `Setting.set` 正是这两条，所以迁移不改行为。

3. **技能轮**：开轮判据换成官方那一条（pi-tui 的 `isUserTurnInitiator` →
   `isUserInvokedSkillPrompt`：类型 + 归属两格都对）。自动加载的技能是 agent 自己塞的
   上下文，不能冒充人说的话。chip 与用户原话都读官方消息自己的 `details`
   （`SkillPromptDetails`：name / prompt / args / lineCount）。

4. **投递**：`command.text` 就是官方 `parseSkillInvocation` 收的那圈正文（chip 渲染为空串），
   把它当 `args` 交给官方的 `buildSkillPromptMessage`。chip 自带 args 时仍以它为准。

5. **工具字形**：18.5.0 新增 `ida` 内建工具，补视图与字形 ——
   那条测试读**装到的那一份** SDK 的 `builtin-names.ts`，上游加名字它就红。

## 后果

- 设置目录继续从上游自报读出来：18.5.0 实测 397 格带 ui（新增 19 格），去掉与桌面端
  无关的 84 格后 **313 格**上屏；新增一节 `IDA Pro`（产品名，刻意不译）。
- 19 格新增设置补了中文标题与说明；`settings-labels.test.ts` 的版本锚（378/294/58）
  同步到 397/313/59，并在注释里写明是 18.5.0 实测。
- 技能轮：chip 在轮终之后还在，用户原话进得了上下文，SKILL.md 不再当助手正文上屏。
  `skill-turn.test.ts` 三条判据在未修复的桥上是 3 fail。
- 期望态的测试夹具从手搓假对象换成官方 `Settings.isolated()`（真在内存里的实现）。
  注意 `isolated({overrides})` 的 override 层**压过** `set()` 落的 global 层，
  所以断言改成读回真实值 + 验 `getProvenance`，不再数一本假账本。
- 仍按 18.3.0 锚定的：`docs/omp/*` 是**带日期的调研快照**（正文自己写了 18.3.0），
  不是当前事实的断言，升级时另行复核，本轮不动。
