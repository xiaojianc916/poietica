# 0043 — 连接的锚只有一个产地，且换锚先把已受理的结清

日期：2026-10-04

## 背景

软件一启动就弹一次「agent 连接失败」，两秒后自愈。日志（`%APPDATA%\Poietica Dev\logs\`）
里失败码是 `AGENT_CAPABILITIES_UNREADABLE`，`failureScope` 是 `operation:read-capabilities`。
它不是对话失败：一条**后台只读**的能力清单请求没等到应答。

实测时序（三条 `open`，探针落在 `ConnectionOwner::open`）：

```
04:12:29.798  open cwd=…\projectless        takeover=Reuse    ← 建出整进程第一条连接
04:12:30.214  open cwd=D:/xiaojianc/poietica takeover=Reuse
04:12:30.215  open cwd=D:/xiaojianc/poietica takeover=Replace  ← 恢复上次对话
04:12:32.145  ERROR AGENT_CAPABILITIES_UNREADABLE
```

两处根因，互相独立：

1. **锚的产地错了。** 那条能力读传 `cwd: None`，被兜底成「无项目」目录；而它是整进程
   第一条请求，于是它**替所有人选了锚**。随后「恢复上次对话」带着账本里的真工作区用
   `Replace` 换掉它 —— 换掉是对的（不同工作区确实该重建），错在那条读根本不该定这个锚。
2. **换锚是破坏性的。** 退休当场 `cancel()`，驱动器把 `pending` 应答槽连同栈一起丢掉，
   已受理、未应答的调用方拿到 `Err(_dropped)` → `Refused(Gone)`。这不是「这条命令失败了」，
   是**受理了却不给答复**。

两个缺陷叠加才是这次弹窗：只有①则锚一致、不会换；只有②则换个锚也不该让用户看见失败。

## 决定

**一、会替整条进程起连接的读，必须带上活动工作区。**

连接的工作区是**对话的属性**，只该由 `open_thread` 这类「打开一条对话」的调用决定
（AGENTS.md §1「任何能力不得绕过会话另立入口」）。但一条进程级读在「没有活连接」时
会自己起一条，那一刻它就在定锚 —— 所以它必须表明锚在哪。

`cwd` 缺席的含义因此收窄成一种：调用方**真的不知道**活动工作区 —— 它退到兜底根，
而兜底根不属于任何人，拿它当锚的连接注定要被换掉。它只是「确实没有更好的答案」时的
最后一格，不是常规路径。

（曾考虑让缺席时先复用活连接的锚。删掉了：`Reuse` 那一档本来就不看 cwd，
`Replace` 无活连接时两条路也相同，只在「`Replace` + 有活连接 + cwd 缺席」这一个格子里
有差别 —— 而那里复用一条**恰好活着**的连接，会让同一条对话的会话桶取决于「此刻有没有
别的连接活着」。那是引入不可预测，不是修缺陷。实测撤掉它测试全绿。）

IPC 面上，本来就能带 `cwd` 的命令（`agent_capabilities`、`agent_toolkit`、`agent_model_catalog`）
带的就是这个值；原先写死 `None` 的五条（能力清单、能力开关、设置目录、改设置、浏览器设置）
补上同一个字段，请求类型收敛成 `AgentWorkspaceRequest`。TS 侧的产地只有一处：
`workspaceRoots.readActive`，与「开新对话」同源。

**二、退休前先把已受理的结清。**

「已受理」的全集是两半：已经发上线的（驱动器 `pending`）与还排在通道里、尚未被读出的
（`AgentClient::queued`）。收摊判据必须两半都空，再退出；期间**照旧服务**，不是停读
（停读只是把排着的那条换个位置丢掉）。对面不回时由 `policy::RETIRE_SETTLE`（2s）兜住，
不让一次换锚永远悬着。

这条与①是两件事：任何**合法**换锚（用户在另一个工作区恢复对话、切工作区）都仍会发生，
而那时在飞的读不该变成用户可见的失败。

## 后果

- 首启恢复上次对话不再重锚：一次起进程、没有弹窗，也不再白扔一次进程起拆。
- `Replace` 的语义没变：cwd 真的不同时照旧重建，只是重建前把在飞的结清。
- 进程级读不再可能替整条进程定锚 —— 定锚是开会话的事。

## 验证

判据落在**起进程次数**与**每条请求都答得上话**上，不落在「谁先跑完」的时序上。

- `crates/conversation-runtime/tests/process-reads-keep-the-live-connection.rs`：
  首启三条并发（进程级读 + 选择器 + 恢复对话）恒起 1 次进程，且三条都给得起答复；
  换工作区的合法重锚那一条，在飞的读也必须被结清。
- `crates/agent-client/tests/retirement-settles.rs`：命令已受理时取消连接，调用方拿到的
  必须是答复而不是 `Gone`。

双向都验过：把①或②任一处撤回，上述用例当场变红，报的正是实机那个 `Refused(Gone)`。
实机冷启动复核：日志无该错误，agent 的会话桶是 `--d--xiaojianc-poietica--`，
两个 `projectless` 桶未被触碰 —— 锚确实落在真工作区上。
